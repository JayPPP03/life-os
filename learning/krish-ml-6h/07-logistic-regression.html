📋 Coach's Review

Common learner gaps in this topic — check yourself against these before the quiz:

  • Reaching for it on regression tasks. Despite the name, logistic regression is classification: spam / not spam, churn / no churn. It outputs a probability; a threshold turns it into a class.
  • Reading h as accuracy, or as a class label. h = 0.9 means P(class = 1) = 90% — a degree of belief, not a correctness score.
  • Missing that the two decision rules are one rule. g(0) = 0.5, so 'predict 1 when g(z) ≥ 0.5' and 'predict 1 when z ≥ 0' describe the same boundary.
  • Training a sigmoid with MSE. That cost surface is non-convex — local minima can trap gradient descent. Log loss stays convex with a well-behaved gradient.
  • Mixing the log-loss branches. y = 1 → cost = −log(h) (punishes a low h); y = 0 → cost = −log(1−h) (punishes a high h).
  • Thinking the sigmoid replaces the linear part. You still compute z = θᵀx first — the sigmoid only squashes z into (0, 1).

✍️ Solve on Paper — Logistic Regression

Close the laptop. This is the pen-and-paper version — the code only works because THIS math works.

The recipe (do these steps, in order, every time):

  1. Linear part: z = θ0 + θ1·x.
  2. Probability: p = 1/(1 + e^(−z)) — first compute e^(−z), then one division. Handy: e⁰ = 1, e¹ ≈ 2.718, e⁻¹ ≈ 0.368, e² ≈ 7.389 (and for below: e^1.2 ≈ 3.320, e^3.6 ≈ 36.60).
  3. Decide: p ≥ 0.5 → class 1 (PASS), else class 0 (FAIL) — the same rule as z ≥ 0.
  4. Log-loss per row: −[y·ln(p) + (1−y)·ln(1−p)], then average over all m rows.

Two things the arithmetic just showed you: (1) confident-and-right is nearly free (0.027) while a confident wrong answer would have been brutally expensive — that asymmetry is exactly what MSE can't express; (2) s2/s3 are mirror images (z = −1.2 vs +1.2), so their probabilities sum to 1 (0.2315 + 0.7685) and their losses are identical — the sigmoid's symmetry, seen in numbers.

📝 Notes

What it is
  • Logistic regression is a classification algorithm. The name is historical — despite saying regression, it predicts discrete classes (spam / not spam, churn / no churn).
  • It first outputs a probability, then a threshold turns that probability into a class label.
Why not just use linear regression?
  • Fit a straight line to 0/1 labels and one outlier drags the best-fit line toward itself, shifting every single prediction.
  • Worse, a line keeps going forever: outputs fall below 0 and above 1 — numbers that cannot be probabilities.
The sigmoid fixes it
z = θᵀx
g(z) = 1 / (1 + e^(−z))
  • The sigmoid squashes any real number into the range (0, 1): very negative z → close to 0, very positive z → close to 1.
  • h = g(z) is the probability that the class is 1. h = 0.9 means the model believes there is a 90% chance of class 1.
The decision rule
predict 1 when g(z) ≥ 0.5 ⇔ z ≥ 0
  • g(0) = 0.5 exactly, so the probability threshold 0.5 is the same boundary as the weighted sum z crossing 0.
  • z = 0 is the tipping point: anything on the positive side of the boundary gets a prediction of 1, anything negative gets 0.
Why not MSE? Enter log loss
  • Feed a sigmoid into MSE and the cost surface becomes non-convex — a bumpy landscape with local minima that can trap gradient descent in a bad spot.
  • Log loss is convex — one clean bowl with a single global minimum — and its gradient is well-behaved, so gradient descent works reliably.
cost(h, y) = −[ y·log(h) + (1−y)·log(1−h) ]
J = (1/m) · Σᵢ cost( h(x⁽ⁱ⁾), y⁽ⁱ⁾ ) — averaged over all m examples
  • If y = 1: cost = −log(h). Confident and right (h → 1) → cost → 0. Confident and wrong (h → 0) → cost explodes.
  • If y = 0: cost = −log(1−h) — the mirror image, punishing a high h.
ELI10

The sigmoid is a squeeze-machine: any number goes in, a probability between 0 and 1 comes out. Log loss is the referee who punishes confident wrong answers brutally and charges almost nothing for confident right ones. MSE only asks are you close? — log loss asks are you confidently right?

🎯 Prove it with your projects

  • Churn model framing: my MyOperator churn model is binary classification — logistic regression is the baseline I name when explaining the 0.5 probability threshold and why precision (+18% QoQ) was the metric, not MSE.
  • Loss function story: the non-convexity argument is exactly why I never train probabilistic classifiers with squared error — log loss keeps the surface convex so gradient descent behaves.
  • Probability intuition: treating churn scores as probabilities (h = 0.8 means 80% churn risk) is what made the 3x high-risk cohort intervention actionable.
