📋 Coach's Review

Common learner gaps in this topic — check yourself against these before the quiz:

  • Calling it lambda in code. Theory says λ; scikit-learn's knob is named alpha. Same concept, different label — mix this up in an interview and it shows you haven't run it.
  • Reading neg MSE wrong. These are negated errors: closer to 0 is better, not 'more negative is better'. Ridge −25.47 beats linear −25.8 precisely because it is nearer zero.
  • Hand-rolling alpha loops. The tool exists: GridSearchCV tries every grid value with CV and hands you .best_params_ / .best_score_. Loop it yourself and you'll misjudge folds.
  • Expecting GridSearchCV to change the model class. It only tunes the grid you hand the estimator you hand it — Ridge stays Ridge.
  • Assuming regularization always lifts the score. On a small, clean dataset the winning alpha can be ≈ 0 (our grid below picked 1e-05, basically plain linear) — there must be overfitting for the penalty to pay rent.
  • Treating a tuned linear model as the finish line. The video's own takeaway: a straight line caps out — real gains come from non-linear models like XGBoost.

import pandas as pd
from sklearn.linear_model import LinearRegression, Ridge, Lasso
from sklearn.model_selection import GridSearchCV, cross_val_score
df = pd.DataFrame({'rooms':      [3, 4, 5, 6, 7],
                   'age_years':  [40, 25, 15, 10, 5],
                   'price_lakh': [50, 65, 85, 100, 120]})
X, y = df.iloc[:, :-1], df.iloc[:, -1]
(no output — data loaded)
In [2] — GridSearchCV over alphas, cv=5
grid = GridSearchCV(Ridge(), param_grid={'alpha': [1e-05, 0.001, 0.1, 1, 10, 100]},
                    scoring='neg_mean_squared_error', cv=5)
grid.fit(X, y)
print(grid.best_params_, round(grid.best_score_, 4))
{'alpha': 1e-05} -12.1337

for a, s in zip(grid.cv_results_['param_alpha'], grid.cv_results_['mean_test_score']):

📝 Notes

Setup: same Boston data
  • Same Boston housing dataset and X/y split as the linear regression practical — only the model and the tuning loop change.
  • The workflow: keep the model fixed, sweep the regularization strength, and let cross-validation decide — no manual trial and error.
Ridge + GridSearchCV
ridge = Ridge() grid = GridSearchCV(estimator=ridge, param_grid={'alpha': [1e-5 ... 100]}, scoring='neg_mean_squared_error', cv=5)
  • In scikit-learn, the theoretical λ is called alpha. The grid stretches over a wide range — alpha values from 1e-5 all the way up to 100 — so both very weak and very strong regularization get a hearing.
  • GridSearchCV tries every alpha in the grid, scoring each with 5-fold CV under neg_mean_squared_error, and keeps the winner.
  • Read it back with .best_params_ (the winning hyperparameters) and .best_score_ (its CV score).
  • Result in the video: best alpha ≈ 100, and the CV score improves from about −37 to about −29.

Quote it like this

Grid search over alpha with 5-fold CV picked alpha = 100 and cut the CV error from about 37 to about 29 — yet the R² still sits near 0.67, which is exactly why the next step is a non-linear model.

Takeaway (spoken in the video)
  • A straight line caps out — keep tuning Ridge/Lasso and you only get marginal gains. For meaningfully better scores, move to non-linear models such as XGBoost.
Key API
GridSearchCV(estimator, param_grid, scoring, cv) → .best_params_, .best_score_
ELI10

Grid search = try every dial setting, keep the winner — with cross-validation as the honest judge of each try.
