📋 Coach's Review

Common learner gaps in this topic — check yourself against every line before the quiz:

  • Multiplying likelihoods without the prior. P(free|spam) alone is NOT the answer — the posterior needs P(spam) × P(free|spam). Skipping the prior is the #1 exam mistake.
  • Confusing the direction. From labeled data you can measure P(word|class), but the question you need is P(class|word) — Bayes theorem is the flip. Writing the fraction backwards is the #2 exam mistake.
  • Dropping the denominator, then reporting raw scores as probabilities. Dropping P(word) is fine for picking the winner, but a real percentage needs the normalization step: divide each score by the sum of all scores.
  • The zero-frequency trap. One word never seen in spam makes P(word|spam) = 0 and the whole product collapses — the fix is Laplace (add-1) smoothing.
  • Forgetting what "naive" buys and costs. It pretends 'free' and 'meeting' never co-occur; real words correlate, yet the class ranking usually stays right — which is why NB is still the text/spam baseline.
  • Trusting the probabilities blindly. NB posteriors are overconfident and poorly calibrated — threshold and rank them, don't read them as true odds.

Step 1 — priors from the labels:

P(spam) = 4/8 = 0.5   ·   P(ham) = 4/8 = 0.5

Step 2 — likelihoods from the word counts (count each word across that class's emails). Spam words: free 3+2+1+2 = 8, meeting 0+0+1+1 = 2 → 10 words total. Ham words: free 0+0+1+0 = 1, meeting 3+2+2+3 = 10 → 11 words total.

P(free|spam) = 8/10 = 0.8    P(meeting|spam) = 2/10 = 0.2
P(free|ham) = 1/11 ≈ 0.0909    P(meeting|ham) = 10/11 ≈ 0.9091

Step 3 — Bayes for the new email (contains 'free'): multiply prior × likelihood for each class. The evidence P(free) is identical for both classes, so it gets dropped — the video's trick.

score(spam) = P(spam) × P(free|spam) = 0.5 × 0.8 = 0.4
score(ham)  = P(ham) × P(free|ham)  = 0.5 × 1/11 ≈ 0.0455

Step 4 — normalize both posteriors (total = 0.4 + 0.0455 = 0.4455 — this total IS the dropped evidence P(free)):

P(spam|free) = 0.4 / 0.4455 ≈ 89.8%   ·   P(ham|free) = 0.0455 / 0.4455 ≈ 10.2% → route to SPAM

Step 5 — flip the evidence, flip the answer. Email containing only 'meeting': score(spam) = 0.5 × 0.2 = 0.1, score(ham) = 0.5 × 10/11 ≈ 0.4545 → P(spam|meeting) = 0.1/0.5545 ≈ 18% → inbox. And 'free free meeting' (counts 2,1): spam = 0.5 × 0.8² × 0.2 = 0.064 vs ham = 0.5 × (1/11)² × (10/11) ≈ 0.0038 → ≈ 94.5% spam. One 'free' next to 'meeting' loses; two 'free's win — word frequency matters.

💡 Business read: a single word swings the routing 90/10, and the posterior is a tunable dial — auto-route only when P(spam) > 0.9 so a real client email mentioning a discount never disappears.

✍️ Solve on Paper — Naive Bayes by Hand

Close the laptop. Pen and paper. The code works because this math works.

The recipe:

  1. Priors: count the labels → P(class) = emails of that class / all emails.
  2. Likelihoods: per word, per class: P(word|class) = class-emails containing the word / class-emails.
  3. Score each class: prior × P(word1|class) × P(word2|class) × …
  4. Normalize: divide each score by the sum of all scores.
  5. Bigger posterior wins.

def nb(counts):   # counts = (free, meeting) word counts
    sp = 0.5 * (0.8)**counts[0] * (0.2)**counts[1]
    ha = 0.5 * (1/11)**counts[0] * (10/11)**counts[1]
    return sp / (sp + ha)

for email, counts in [("only 'meeting'", (0, 1)), ("'free free meeting'", (2, 1))]:
    p = nb(counts)
    print(f"{email:20s} P(spam) = {p:.4f} -> {'SPAM' if p > .5 else 'HAM'}")

📝 Notes

The big idea
  • Naive Bayes is a classification algorithm built entirely on conditional probability and Bayes theorem: given some evidence (the feature values of a row), update how likely each class is, and predict the class with the highest updated probability.
Step 1 · Independent events — the dice example
  • Roll two dice. The second die knows nothing about the first, so the two events are independent: the joint probability is simply the product. P(two sixes) = 1/6 × 1/6 = 1/36.
Independent events: P(A∩B) = P(A) · P(B)
Step 2 · Dependent events — the marbles example
  • Now draw two marbles from a bag without putting the first one back. The first draw changes the bag, so the events are dependent: multiply the first probability by the probability of the second event given the first.
Dependent events: P(A∩B) = P(A) · P(B|A)
Step 3 · Deriving Bayes theorem
  • Write the joint probability two ways: P(A∩B) = P(B|A)·P(A) and also P(A∩B) = P(A|B)·P(B). Set them equal and rearrange:
P(A|B) = P(B|A) · P(A) / P(B)
  • Read it as: posterior = (likelihood × prior) / evidence. It reverses the conditioning — from P(B|A) we get P(A|B).
Naive Bayes for machine learning
  • Goal: given features x1…xn, find the most probable class: P(y|x1,…,xn).
  • Bayes theorem flips it around: numerator = P(y) · Π P(xi|y), denominator = P(x1,…,xn). The denominator is the same for every class — a constant — so it is dropped:
P(y|x1,…,xn) ∝ P(y) · Π P(xi|y)
  • Naive = the model assumes all features are independent of each other given the class, so it just multiplies per-feature likelihoods and ignores feature interactions.
Worked example — the tennis dataset
  • 14 rows: 9-yes / 5-no → P(Yes) = 9/14, P(No) = 5/14. Every categorical feature gets its own little count table.
  • Outlook count table: Sunny 2-yes / 3-no · Overcast 4-yes / 0-no · Rain 3-yes / 2-no.
  • Query (Sunny, Hot): multiply prior × likelihoods → unnormalized score Yes ≈ 0.31, score No ≈ 0.857.
  • Normalize: 0.31 / (0.31 + 0.857) ≈ 27% vs ≈ 73% → predict No. Same dropped-denominator trick: only the relative size of the two scores matters.
  • Homework assigned in the video: repeat the same calculation for (Overcast, Mild).
💡 Interview angle: why is it called naive? Because the feature-independence assumption is almost never true in real data — yet the classifier still works remarkably well, which is exactly why it remains the classic baseline for text and spam problems.
