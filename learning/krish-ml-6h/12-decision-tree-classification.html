🤔 Why this formula — feel the intuition

🎯 The business problem: the COO will not read a model — but she WILL act on a rule she can say out loud: "IF the customer complained AND tenure < 12 months THEN flag them high risk." A decision tree promises exactly that. The entire game reduces to one question: which question do we ask first?

🧠 Why THIS formula:

  • Entropy H = −Σ p·log₂p is a surprise meter. Open a pure node (all churners) and nothing can surprise you → H = 0. Open a 50/50 node and every draw is a coin flip → maximum confusion, H = 1. The minus sign is bookkeeping: logs of fractions are negative, the minus flips them positive. Without a single number for "how mixed is this pile?", picking the first question is vibes — entropy turns "which feature first?" into arithmetic.
  • Information gain = parent H − Σ (|child|/|parent|)·H(child): how much uncertainty THIS question removes. The size-weighting is not decoration: a split producing one tiny pure branch and one huge messy branch must NOT look good — those are the 47-vs-1 memorization splits that train perfectly and predict garbage. Skip the weights and you promote exactly that fraud. In our table: "Complained?" removes 0.459 of entropy, "Contract" removes 0.082 — so the root asks about complaints, and retention calls complainers first.
  • Why log₂ specifically: entropy is measured in BITS — the currency of information. A 50/50 node holds exactly 1 bit: one good yes/no question could resolve it. Gain = 0.459 literally means this question hands back about half a bit. Any other log base would rank splits identically — log₂ just makes the number read as "yes/no questions saved".

📈 See it: the best split drains surprise out of the pile — one branch nearly solved, one solved completely.

💬 Feel it: the game of 20 questions. Ask "is it a living thing?" and half the universe dies with one answer; ask "is it your left shoe?" and you have learned almost nothing. Entropy is how mixed your possibility pile still is; information gain is how much shuffling each question bought you. The tree is just a machine that greedily asks the best-scoring question, level after level, until the pile is pure.

🔗 This intuition powers everything below.

📋 Coach's Review

Common learner gaps in this topic — check yourself against every line before the quiz:

  • Sign errors in entropy. H = −Σ p·log₂p: log₂(0.25) is −2, so that term is −0.25×(−2) = +0.5. Forget the leading minus and "entropy" comes out negative.
  • Forgetting to WEIGHT the child entropies. Gain = parent H − Σ(|child|/|parent|)·H(child); averaging children equally (or skipping the weights) is the classic wrong answer.
  • Reading gain as causation. A high-gain feature is the best splitter on this sample — the measure is biased toward many-valued features and explains nothing about WHY customers leave.
  • Gini vs entropy confusion. Same job: Gini = 1 − Σp², no logarithm, computationally faster — which is exactly why scikit-learn defaults to it; both pick near-identical splits.
  • The scaling myth. Splits compare a value against a threshold, so trees need NO feature scaling — the exact opposite of distance-based KNN.
  • Unbounded depth = memorization. Pure leaves that isolate single rows train perfectly and predict badly; control with max_depth / min_samples_leaf (pre-pruning, tuned via GridSearchCV) or cut after growth (post-pruning).

Handy log₂ values: log₂(0.5) = 1 · log₂(0.75) ≈ 0.415 · log₂(0.25) = 2 · log₂(0.667) ≈ 0.585 · log₂(0.333) ≈ 1.585  (log₂ of a fraction is negative — the minus sign in H = −Σp·log₂p flips it back to positive).

Step 1 — root entropy (all 6 rows: 3 churned / 3 stayed → p = 0.5 each):

H(S) = −0.5·log₂(0.5) − 0.5·log₂(0.5) = −0.5(−1) − 0.5(−1) = 1.0 ← maximum impurity

Step 2 — split on "Complained?":

Yes branch (4 rows: 3 churn / 1 stay → p = 0.75 / 0.25):
H = −0.75·log₂(0.75) − 0.25·log₂(0.25) = 0.75×0.415 + 0.25×2 = 0.311 + 0.5 = 0.811
No branch (2 rows: 0 churn / 2 stay) → pure node → H = 0

weighted = (4/6)×0.811 + (2/6)×0 = 0.541 + 0 = 0.541
Gain(S, Complained) = 1 − 0.541 = 0.459

Step 3 — split on "Contract":

Monthly (3 rows: 2 churn / 1 stay → p = 0.667 / 0.333):
H = −0.667·log₂(0.667) − 0.333·log₂(0.333) = 0.667×0.585 + 0.333×1.585 = 0.390 + 0.528 = 0.918
Annual (3 rows: 1 churn / 2 stay) → mirror image → H = 0.918

weighted = (3/6)×0.918 + (3/6)×0.918 = 0.918
Gain(S, Contract) = 1 − 0.918 = 0.082

Step 4 — compare and build: Gain(Complained) = 0.459 ≫ Gain(Contract) = 0.082 → the root asks "did they complain?" Its No branch is already a pure stay-leaf (stop growing there); only the Yes branch splits again — and there rows 3 and 4 have identical features (Yes, Annual) but different labels, so no feature can ever separate them: that leftover uncertainty is real, not a modeling failure.

💡 Business read: complaints are the retention alarm — call complainers first. Contract type barely separates (gain 0.082): it is a second-order follow-up question, not the root.

✍️ Solve on Paper — Entropy & Information Gain by Hand

Close the laptop. Pen and paper. The code works because this math works.

The recipe:

  1. Write the table. Count the classes at the root (churn vs stay) and compute the root entropy H(S).
  2. Pick one feature and split the rows into branches — one branch per value.
  3. Per branch: count churn/stay and compute H = −p·log₂(p) − (1−p)·log₂(1−p). A pure branch has H = 0.
  4. Weight the branch entropies by size: weighted = Σ (branch rows ÷ total) × H(branch).
  5. Gain = H(root) − weighted. The feature with the biggest gain becomes the root question.
  6. Repeat inside each impure branch until every leaf is pure (or you run out of features).

Gain(S, Complained) = 1.0 − 1.0 = 0 ← this question tells you NOTHING

Both branches are exactly as mixed as the parent. A feature can exist and still be worthless — entropy proves it with one number, no vibes needed.

Step 3 — split on "Refund?" (Yes: rows 1, 2, 3, 5 → 3 churn / 1 stay; No: rows 4, 6, 7, 8 → 1 churn / 3 stay):

Yes branch (p = 0.75 / 0.25): H = −0.75·log₂(0.75) − 0.25·log₂(0.25)
    = −0.75(−0.415) − 0.25(−2) = 0.311 + 0.5 = 0.811
No branch (p = 0.25 / 0.75): mirror image → H = 0.811

weighted = (4/8)×0.811 + (4/8)×0.811 = 0.811
Gain(S, Refund) = 1.0 − 0.811 = 0.189

Step 4 — the root decision: Gain(Refund) = 0.189 > Gain(Complained) = 0 → the tree asks "did we issue a refund?" first. Both branches are still impure (0.811 each), so each keeps splitting — which is where the third column earns its keep.

Your turn: compute the information gain of Tenure < 12 mo? — Yes branch: rows 1–5 (4 churn / 1 stay, so p = 0.8; use log₂(0.8) ≈ 0.322 and log₂(0.2) ≈ 2.322); No branch: rows 6–8 (0 churn / 3 stay). Mind the branch sizes — they are NOT 50/50 this time. Does it beat Refund's 0.189?

Attempt first, then open the full solution

Step 1 — Yes branch (5 rows: 4 churn / 1 stay, p = 0.8):

H = −0.8·log₂(0.8) − 0.2·log₂(0.2) = 0.8×0.322 + 0.2×2.322 = 0.258 + 0.464 = 0.722

Step 2 — No branch (3 rows: 0 churn / 3 stay): pure node → H = 0.

Step 3 — weight by size (5 of 8 vs 3 of 8):

weighted = (5/8)×0.722 + (3/8)×0 = 0.451 + 0 = 0.451
Gain(S, Tenure < 12 mo) = 1.0 − 0.451 = 0.549

Verdict: 0.549 > 0.189 > 0 — full ranking: Tenure < 12 mo ≫ Refund ≫ Complained. The tenure split wins the root, and its No branch is already a pure stay-leaf; only the 5-row Yes branch (H = 0.722) needs more questions. And note the trap you just avoided: weighting by 0.5/0.5 instead of 5/8 and 3/8 is the classic entropy mistake.

In [2] — entropy from scratch, root node
import math
def entropy(labels):
    n = len(labels)
    h = -sum((c/n) * math.log2(c/n) for c in labels.value_counts() if c > 0)
    return 0.0 if abs(h) < 1e-12 else h   # pure node: entropy is exactly 0 (kills -1e-16 float noise)

root = entropy(df.churned)
print(f"root: {df.churned.value_counts().to_dict()}  H = {root:.3f}")
root: {'Yes': 3, 'No': 3} H = 1.000
In [3] — information gain for BOTH candidate features
def split_info(col):
    weighted = 0
    for v, sub in df.groupby(col):
        h = entropy(sub.churned)
        weighted += len(sub)/len(df) * h
        print(f"  {col}={v}: {sub.churned.value_counts().to_dict()}  H={h:.3f}")
    gain = root - weighted
    print(f"  weighted entropy = {weighted:.3f}  gain = {gain:.3f}\n")
    return gain

g_comp = split_info('complained')
g_cont = split_info('contract')
print("root feature:", 'complained' if g_comp > g_cont else 'contract',
      f"(gain {max(g_comp, g_cont):.3f} vs {min(g_comp, g_cont):.3f})")

📝 Notes

The big idea
  • A decision tree is a set of nested IF-ELSE conditions learned from data — the same if/else you would write by hand, but the questions and their order are chosen automatically by an algorithm.
  • Root node: the first split. Internal nodes: further splits. Leaf nodes: the final output — the predicted class.
Splitting the tennis dataset
  • Root = all 14 rows: 9-yes / 5-no → mixed, i.e. impure.
  • Split on Outlook: Sunny → 2-yes / 3-no (still impure), Overcast → 4-yes / 0-no (pure — stop; leaf says Yes), Rain → 3-yes / 2-no (impure → split again).
  • Pure node = all rows belong to one class. Impure node = mixed classes. The tree always picks the split that makes children as pure as possible.
Entropy — measuring impurity
H(S) = −p₊·log₂(p₊) − p₋·log₂(p₋)
  • H(S) = 0 for a pure node and reaches its maximum of 1 at 50/50. The 9/5 root gives H ≈ 0.94 — very impure.
Gini impurity — the faster cousin
Gini = 1 − Σ pᵢ²
  • 0 for a pure node, maximum 0.5 for binary classes at 50/50.
  • No logarithm → computationally faster than entropy; it is the default criterion in scikit-learn.
Information gain — choosing the best feature
Gain(S, feature) = H(S) − Σ (|Sᵥ|/|S|) · H(Sᵥ)
  • Parent entropy minus the size-weighted average of the child entropies. Bigger gain = better split.
  • Video worked example: root H(S) = 0.94. feature1 → weighted child entropy ≈ 0.89 → gain ≈ 0.041 (barely purifies anything). feature2 → gain ≈ 0.51 (huge). Pick feature2.
Continuous features
  • Sort the values, test each candidate threshold between consecutive points, compute the gain for every threshold, and keep the best one — that is how numeric columns become tests like x < 6.5.
Pruning — controlling overfitting
  • Post-pruning: grow the full tree first, then cut branches that add nothing. Video example: a split separating 47 samples from just 1 is pure memorization and should be cut.
  • Pre-pruning: stop growth early via hyperparameters — max_depth, min_samples_leaf, etc. — typically searched with GridSearchCV.
💡 Interview angle: do decision trees need feature scaling? No. Splits compare a value against a threshold, so units and scales do not matter — a sharp contrast with distance-based models like KNN.
