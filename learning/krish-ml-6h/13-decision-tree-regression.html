📋 Coach's Review

Common learner gaps in this topic — check yourself against every line before the quiz:

  • Expecting a line. A regression tree outputs piecewise-constant stairs — every point in a leaf gets the same number, and anything beyond the training range (say a 36-month contract) can never be extrapolated.
  • Forgetting the leaf stores the MEAN. The mean is the constant that minimizes squared error; switch the criterion to MAE and the leaf would store the median instead.
  • Skipping the size-weighting. Split quality = (|left|/n)·MSE_left + (|right|/n)·MSE_right — comparing raw child MSEs without the weights picks the wrong split.
  • Trusting an unweighted-looking win. One tiny pure child plus one huge messy child can look great until the weighting exposes it — always recompute the weighted number.
  • Growing to single-row leaves. Train MSE hits exactly 0 while test performance collapses — the same overfitting story as classification; cap with max_depth / min_samples_leaf.
  • The scaling myth. Threshold splits ignore units entirely — no standardization needed, unlike KNN or penalized regression.

Step 1 — the root: no split, one constant for everyone (a regression tree leaf stores the MEAN):

root mean = (2+4+6+10+12+16)/6 = 50/6 ≈ 8.333
MSE = ((2−8.333)² + (4−8.333)² + (6−8.333)² + (10−8.333)² + (12−8.333)² + (16−8.333)²)/6
    = (40.111 + 18.778 + 5.444 + 2.778 + 13.444 + 58.778)/6 = 139.333/6 ≈ 23.222 ← the baseline to beat

Step 2 — candidate split A: "months < 6" (left {2,4}, right {6,10,12,16}):

left mean = (2+4)/2 = 3      → MSE = ((2−3)² + (4−3)²)/2 = 2/2 = 1.0
right mean = (6+10+12+16)/4 = 11 → MSE = (25+1+1+25)/4 = 52/4 = 13.0
weighted = (2/6)×1.0 + (4/6)×13.0 = 0.333 + 8.667 = 9.0

Step 3 — candidate split B: "months < 12" (left {2,4,6}, right {10,12,16}):

left mean = (2+4+6)/3 = 4 → MSE = (4+0+4)/3 = 8/3 ≈ 2.667
right mean = (10+12+16)/3 = 38/3 ≈ 12.667 → MSE = (7.111 + 0.444 + 11.111)/3 = 18.667/3 ≈ 6.222
weighted = (3/6)×2.667 + (3/6)×6.222 = 1.333 + 3.111 = 4.444

Step 4 — pick the winner: 4.444 < 9.0 → split at months < 12. MSE drops 23.222 → 4.444, an 81% cut. Leaf means: short contracts predict ₹4k, long contracts predict ₹12.667k.

Step 5 — predict the 18-month prospect: 18 ≥ 12 → right leaf → ₹12.667k/month. A 13-month customer gets the identical number — the model is piecewise-constant: everything landing in a leaf gets that leaf's mean. No line, no extrapolation.

💡 Business read: the tree just priced the sales incentive — moving a customer past the 12-month threshold is worth ≈ ₹8.7k/mo more (12.667 vs 4). Grow the tree deeper and it starts memorizing individual customers (train MSE → 0); that is exactly what depth/leaf-size limits are for.

In [3] — both candidate splits, weighted MSE decides
def mse_after(threshold):
    L, R = df[df.months < threshold], df[df.months >= threshold]
    mL, mR = L.revenue.mean(), R.revenue.mean()
    mseL, mseR = ((L.revenue - mL)**2).mean(), ((R.revenue - mR)**2).mean()
    w = len(L)/len(df) * mseL + len(R)/len(df) * mseR
    print(f"split months < {threshold}: left mean={mL:.4f} (MSE {mseL:.4f}), "
          f"right mean={mR:.4f} (MSE {mseR:.4f}), weighted MSE={w:.4f}")
    return w

w6, w12 = mse_after(6), mse_after(12)
print("pick months < 12" if w12 < w6 else "pick months < 6",
      f"-> MSE {mse_root:.3f} dropped to {min(w6, w12):.3f}")

📝 Notes

The big idea
  • Decision Tree Regression uses the same tree structure as classification — root node, internal nodes, leaf nodes, nested IF-ELSE splits — but the target is a continuous number instead of a class.
  • Each leaf stores the MEAN of the training targets that reached it. That stored mean IS the prediction for anything that lands in the leaf.
What changes: the split criterion
  • Classification scored splits with entropy/Gini. Regression instead picks the split that reduces MSE the most (MAE reduction also works) — in other words, children whose target values are as tightly grouped as possible.
Split quality = reduction in MSE (or MAE)
Worked example from the video
  • 5 rows with outputs 20, 24, 26, 28, 30. The root predicts the mean of everything: 128/5 = 25.6. Root MSE ≈ 13.8 (video figure) — large, because one constant must fit all five targets.
  • Split on feature F1: node1 receives {20, 24, 26} → leaf mean 23.33; node2 receives {28, 30} → leaf mean 29.
  • Within-node MSE is now much smaller than at the root — the split bought purity in the MSE sense.
  • Split deeper: each further split shrinks within-node error again, and the tree keeps going until leaves (or a stopping rule) are reached.
Why the mean?
  • The mean is the constant that minimizes squared error, so storing the leaf mean is the best possible constant guess for everything in that leaf — the regression mirror of a classification leaf storing the majority class.
Making a prediction
  • A new point walks down the IF-ELSE path and the output is simply the mean of the leaf it lands in. The model is piecewise-constant: every point in the same leaf gets the same value.
Overfitting warning
  • Split forever and every leaf ends up holding a single training row — training MSE = 0, test performance garbage. Control it with depth / leaf-size limits: the same pre- and post-pruning ideas as classification.
💡 Interview angle: tree-family models — classification or regression — need no feature scaling, because splits compare values against thresholds. Contrast that with KNN, which lives and dies by distances.

🎯 Prove it with your projects

  • The reco engine predicts continuous affinity scores, and bucket-then-average thinking — predict the mean behavior of the group a user falls into — is literally what a regression tree leaf stores.
  • I keep regression trees honest with the same pruning discipline as classification: depth and leaf-size tuned on validation only, never trusting training MSE.
  • Never train on the future: my reco temporal split is the regression-tree version of judging splits by held-out error instead of how good the training numbers look.
