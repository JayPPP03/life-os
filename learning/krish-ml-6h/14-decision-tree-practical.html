🧮 Worked Mini-Project — Support-desk triage: 6 tickets, every gini number calculated

Business problem: a MyOperator-style support desk wants a rule for auto-resolve vs escalate-to-human. Last week's tickets:

Ticketcomplaints/weektenure (months)escalated?
T182yes
T263yes
T339yes
T424no
T518no
T6412no

Step 1 — impurity at the root. 3 yes, 3 no:

gini = 1 − (3/6)² − (3/6)² = 1 − 0.25 − 0.25 = 0.5 (maximum disorder)

Step 2 — try candidate splits, weight the children. Node gini = 1 − Σ p². Example: complaints ≤ 5 → left {T3,T4,T5,T6} = 1 yes/3 no → gini = 1 − (1/4)² − (3/4)² = 0.375; right {T1,T2} = 2 yes/0 no → gini = 0. All four candidates (verified in the lab below):

complaints ≤ 5   : (4/6)(0.3750) + (2/6)(0) = 0.2500 → reduction 0.5 − 0.25 = 0.2500 ← WINNER
complaints ≤ 3.5 : (3/6)(0.4444) + (3/6)(0.4444) = 0.4444 → reduction 0.0556
tenure ≤ 5.5     : (3/6)(0.4444) + (3/6)(0.4444) = 0.4444 → reduction 0.0556
tenure ≤ 8.5     : (4/6)(0.5000) + (2/6)(0.5000) = 0.5000 → reduction 0.0000 (useless split)

Step 3 — the tree picks complaints ≤ 5, then repeats this exact computation at every child node until every leaf is pure — that is what max_depth=None means. The business rule it found: 'more than 5 complaints in a week → escalate'.

Step 4 — but unlimited growth memorizes. Real iris run (lab below): the unpruned tree hits train 100% / test 93.3% and grows 8 leaves, 5 of which hold a single sample — the video's 47-vs-1 disease. Add mild noise to the features and it collapses to 57.8% test, while a max_depth=2 tree holds 73.3%. The depth cap is cheap insurance against noise-chasing.

💡 Business reading: a tree's value to an ops team is the AUDITABLE rule ('>5 complaints → escalate'), not the train score. Inspect with plot_tree(filled=True), cut the silly branches, then re-check both accuracies.

In [1] — the 6-ticket dataset + verify the hand gini math
import pandas as pd
df = pd.DataFrame({'complaints': [8, 6, 3, 2, 1, 4],
                   'tenure':     [2, 3, 9, 4, 8, 12],
                   'escalated':  ['yes', 'yes', 'yes', 'no', 'no', 'no']})

def gini(s):
    p = s.value_counts(normalize=True)
    return 1 - (p ** 2).sum()

print("root gini:", round(gini(df.escalated), 4))
for col, thr in [('complaints', 5.0), ('complaints', 3.5), ('tenure', 5.5), ('tenure', 8.5)]:
    L, R = df[df[col] <= thr].escalated, df[df[col] > thr].escalated
    w = (len(L) * gini(L) + len(R) * gini(R)) / len(df)
    print(f"{col} <= {thr}: left n={len(L)} gini={gini(L):.4f} | right n={len(R)} gini={gini(R):.4f} | weighted={w:.4f} | reduction={gini(df.escalated)-w:.4f}")

In [2] — iris: unlimited growth vs max_depth=2 (clean data)
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

iris = load_iris()
Xtr, Xte, ytr, yte = train_test_split(iris.data, iris.target, test_size=0.3,
                                      random_state=42, stratify=iris.target)
print("train/test sizes:", Xtr.shape[0], Xte.shape[0])

full = DecisionTreeClassifier(criterion='gini', random_state=42).fit(Xtr, ytr)
print("FULL tree: depth =", full.get_depth(), "leaves =", full.get_n_leaves(),
      "train acc =", full.score(Xtr, ytr), "test acc =", full.score(Xte, yte))
pruned = DecisionTreeClassifier(criterion='gini', max_depth=2, random_state=42).fit(Xtr, ytr)
print("DEPTH-2  : depth =", pruned.get_depth(), "leaves =", pruned.get_n_leaves(),
      "train acc =", pruned.score(Xtr, ytr), "test acc =", pruned.score(Xte, yte))

📝 Notes

The setup

This section is hands-on: load the classic iris dataset, split it into train/test, and fit sklearn's DecisionTreeClassifier. The real lesson is not the dataset — it is learning to SEE a tree overfit, and then cut it back.

The constructor knobs
  • DecisionTreeClassifier() with no arguments uses criterion='gini'. The options are 'gini' and 'entropy' — both measure the impurity of a split.
  • splitter is 'best' by default (always take the best split found at a node); the alternative is 'random'.
  • Growth controls (pre-pruning): max_depth, min_samples_leaf, max_features. Leave them unset and the tree keeps splitting until every leaf is pure.
A fully grown tree overfits — and you can see it

With no limits the tree memorizes noise. In the video, the fitted tree shows a silly split: one branch holds 47 samples while the other holds just 1. A 1-sample leaf is the tree memorizing one odd row — that branch should be cut. Cutting back an already-grown tree is POST-PRUNING.

Seeing it: plot_tree
plot_tree(model, figsize=(15,10), filled=True)

filled=True colours every node by its majority class, so tiny, impure, pointless leaves jump out of the picture. You eyeball the plot, spot the silly branches, then re-fit with limits.

fit() before predict() — always

model.fit(X_train, y_train) must run before model.predict(...). Call predict on an unfitted estimator and sklearn raises a NotFittedError. Obvious — but it bites everyone once.

Judge it on train AND test accuracy

Score the model on both sets. A fully grown tree: very high train accuracy, clearly lower test accuracy — that gap IS the overfitting. Prune or cap the depth and the gap narrows while the test score rises.

💡 Interview angle: 'Train accuracy 99%, test accuracy 78% — what do you do?' → the tree memorized the train set; restrict growth (max_depth, min_samples_leaf) or post-prune the tiny leaves you can see in plot_tree, then re-check both scores.

🎯 Prove it with your projects

  • Post-pruning is my validation-tuning discipline in miniature: for the reco engine I grid-searched SVD rank + α on VALIDATION only and touched the test set exactly once — the same rule as cutting tree branches based on inspected evidence instead of test-set peeking.
  • Action item: the next tree I fit gets a plot_tree(..., filled=True) pass first — I hunt for 47-vs-1 style leaves before trusting any score.
