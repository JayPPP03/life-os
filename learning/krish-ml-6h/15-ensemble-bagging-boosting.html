① Who trains in parallel? Bagging members are independent and train IN PARALLEL; only boosting is sequential. Saying 'bagging models fix each other's errors' is the classic swap.
② Bootstrap = WITH replacement. A row can repeat inside one subset (the worked project shows C5 drawn 3×) and be absent from another — not 'split the data into parts'.
③ Vote vs average. Classification aggregates by MAJORITY VOTE; regression by the MEAN. Quoting one for both tasks loses the point.
④ What bagging actually reduces. Averaging diverse members cancels their errors — it attacks VARIANCE. (Boosting attacks bias by chaining weak learners.)

✍️ Solve on Paper — Bagging by Hand

Close the laptop. Pen and paper. The code works because this math works.

The recipe:

  1. Write the n training rows. Draw a bootstrap sample of n draws WITH replacement — duplicates allowed, and some rows will be missed.
  2. Train member 1 on its sample only; write down what it answers.
  3. Draw fresh samples and train members 2, 3, … — every draw independent, all members in parallel.
  4. Aggregate: classification = majority vote; regression = average of the numbers.
  5. Boosting contrast: same rows, but SEQUENTIAL — each new weak learner concentrates on the rows the members before it got wrong.

Worked practice — a promo desk with 6 customers A–F: one dataset, two aggregations. Class target = clicked the promo? Regression target = watch-minutes/week.

Step 1 — three bootstrap samples (with replacement, written out draw by draw):

S1 = A, C, C, C, E, F → C drawn 3×; B and D never drawn
S2 = B, B, D, D, E, F → B and D 2× each; A and C never drawn
S3 = A, D, D, E, E, E → E drawn 3×; B, C, F never drawn

Both bagging signatures by hand: rows REPEAT inside a sample (with replacement), and roughly a third of the rows miss each draw.

Step 2 — each member answers for a new customer G. Our members are one-leaf trees: each answers with the majority class it drew (class case) or the mean of its drawn targets (regression case).

Member 1 (S1): 5 Yes / 1 No → votes Yes  ·  mean = (4+10+10+10+20+6)/6 = 60/6 = 10
Member 2 (S2): 1 Yes / 5 No → votes No  ·  mean = (25+25+4+4+20+6)/6 = 84/6 = 14
Member 3 (S3): 4 Yes / 2 No → votes Yes  ·  mean = (4+4+4+20+20+20)/6 = 72/6 = 12

Step 3 — aggregate:

classification: Yes : No = 2 : 1 → MAJORITY Yes (member 2 is outvoted — its error gets cancelled)
regression: (10 + 14 + 12)/3 = 36/3 = 12.0 min/wk

Boosting in one line: run the members sequentially instead — member 2 re-weights the rows member 1 got wrong, member 3 re-weights member 2's mistakes — a chain of weak specialists, not a parallel vote.

In [5] — the ~1/3 out-of-bag law, simulated
r = np.random.RandomState(0)
n, trials, miss = 6, 100000, 0
for _ in range(trials):
    if 0 not in r.randint(0, n, n):
        miss += 1
print("simulated P(row never drawn) =", miss / trials,
      "| theory (1-1/6)^6 =", (1 - 1/6) ** 6, "| 1/e =", 1 / np.e)

📝 Notes

Ensemble = combine multiple models

One model is one opinion. An ENSEMBLE trains several models and merges their outputs so the combined verdict beats any single member. Bagging and boosting are the two classic ways to do that merging.

Bagging = Bootstrap AGGregation
  1. Create subsets of the data by RANDOM ROW SAMPLING WITH REPLACEMENT — the bootstrap. A row can appear multiple times in one subset (and not at all in another).
  2. Train a different model on each subset — usually decision trees — IN PARALLEL. The members never depend on each other.
  3. AGGREGATE the outputs: majority vote for classification, mean for regression.

Because each model saw a slightly different version of the data, its errors differ from its teammates' errors; aggregating cancels many of them out. How many models? Think 100-200 — with that many voters, a tied vote is practically impossible, so the final answer is stable.

Boosting = sequential error-fixing

Boosting also combines many models, but trains them SEQUENTIALLY. Each new WEAK LEARNER is built to fix the errors the models before it made; chain enough of them and the sequence becomes a STRONG LEARNER.

The teacher analogy

One teacher each for physics, chemistry, maths and geography: every specialist steps in exactly where the previous ones fell short. That is the video's mental model for boosting — a chain of specialists on the leftover mistakes.

One-line contrast
Bagging: parallel models on bootstrap samples → vote / average · Boosting: sequential weak learners, each correcting the previous ones → strong learner

Random forest (next section) is bagging with decision trees; AdaBoost (a later section) is boosting.

💡 Interview angle: 'Bagging vs boosting in one line?' — Bagging trains independent models in parallel on bootstrap samples to stabilize the prediction; boosting trains them one after another so each new weak learner fixes the errors of its predecessor.
