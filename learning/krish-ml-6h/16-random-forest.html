① The SECOND sampling. RF does row bootstrap AND feature sampling per tree. Skipping feature sampling misses the whole point: it is what DECORRELATES the trees so their errors can cancel.
② What averaging reduces. Averaging many decorrelated trees cuts the VARIANCE term; the bias stays roughly the same. 'Bagging reduces bias' is the classic wrong answer.
③ Normalization question. RF needs NO scaling/standardization — threshold splits are scale-invariant. KNN DOES need it (distances). This exact pair is drilled in the video.
④ Outlier question. RF barely cares (a threshold split shrugs off extreme values); KNN cares a lot (an outlier warps distances). The second half of the pair.
⑤ Both tasks. The same forest does classification (majority vote) AND regression (average of tree outputs) — learners often assume classification only.
⑥ Deeper is not better. Each member is DELIBERATELY an overfit, low-bias tree; variance control comes from the aggregation, not from tuning each tree's depth.

✍️ Solve on Paper — Random Forest

Close the laptop. Pen and paper. The code works because this math works.

The recipe:

  1. Bootstrap the rows: draw 6 rows WITH replacement — duplicates are allowed, some rows are never drawn.
  2. Restrict the features: hand each tree only a random subset of the columns.
  3. Grow the tree on exactly what it received: the split that best separates churn/stay on ITS rows and columns.
  4. Repeat for every tree in the forest — different rows, different columns.
  5. Predict with every tree, then take the majority vote.

Three copies of one opinion ≈ one tree: variance never drops, and wherever the lone tree is wrong, the forest is wrong in unison. The row bootstrap + feature subset make the trees DISAGREE — and the majority of disagreeing voters is what cancels errors.

📝 Notes

Random forest = bagging with decision trees

Take the bagging recipe and use DECISION TREES as the member models. Many trees standing together = a forest. Each tree trains on its own bootstrap sample of rows.

Two samplings per tree — not one
  1. ROW sampling: the bootstrap — rows drawn with replacement.
  2. FEATURE sampling: each tree also sees only a random subset of the features (columns).

So every tree sees different rows AND different columns, which makes the trees different from each other (decorrelated). That diversity is exactly what makes the aggregation work — identical trees would just repeat identical mistakes.

Why the forest exists

A single fully grown decision tree is LOW BIAS but HIGH VARIANCE: it hugs the training data — noise included — and changes wildly when the data changes. That is overfitting. Average many trees trained on different row and feature samples: the bias stays roughly the same while the VARIANCE term shrinks hard. That is the entire point of the forest.

How the forest predicts
Classification: every tree votes → MAJORITY vote wins · Regression: average of all tree outputs

Same aggregation as bagging — random forest is just bagging specialized to trees, and it handles both classification and regression.

💡 Interview angle — the nuggets drilled in the video:

  • Does random forest need normalization / standardization? NO — splits compare values against thresholds, which are scale-invariant.
  • Does KNN need it? YES — KNN uses distances, so a big-scale feature would dominate them.
  • Is random forest impacted by outliers? NOT much — a threshold split shrugs off extreme values.
  • Is KNN impacted by outliers? YES — an outlier warps the distances around it.
  • Can random forest do both classification and regression? YES.
