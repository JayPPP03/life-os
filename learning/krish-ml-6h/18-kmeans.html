📋 Coach's Review

Common learner gaps in this topic — check yourself against each before the quiz:

① K is an input, not an output.
You choose K up front; k-means never discovers it. Choosing K is a separate job (elbow here, silhouette in topic 20).
② Assignment alone is not k-means.
The update step — recompute each centroid as the MEAN of its assigned points — is half the algorithm. Assign once and stop and you have not run k-means.
③ Calling k-means++ "just random".
It deliberately spreads the starting centroids far apart. Two centroids landing in one dense region — the classic bad start — is exactly what it prevents.
④ Reading the lowest WCSS as the answer.
WCSS always falls as K grows (it hits 0 when K = number of points). You pick the ELBOW — the bend of the curve — not the minimum.
⑤ Ignoring feature scale.
Here spend runs 20-65 and visits 4-27; Euclidean distance lets the wider-range feature dominate. Real pipelines standardize before clustering.
⑥ Expecting k-means to absorb outliers safely.
Every point must join a cluster, so extreme customers drag the mean-based centroids off target. DBSCAN (topic 21) is the outlier-safe alternative.

✍️ Solve on Paper — K-Means

Close the laptop. Pen and paper. The code works because this math works.

The recipe (K=2):

  1. Place 2 starting centroids.
  2. Assign: Euclidean distance d = √((x₂−x₁)² + (y₂−y₁)²) from every point to BOTH centroids — nearest wins.
  3. Update: each centroid = the MEAN of its assigned points.
  4. Reassign against the moved centroids; note who switched.
  5. Repeat until assignments stop changing → converged.

📝 Notes

The big idea: unsupervised learning

K-Means is an unsupervised algorithm: the data has no output labels. Nobody hands the model the right answer — the goal is to group similar points into K clusters, where K is a number chosen up front. The flagship use case is customer segmentation for targeted ad / marketing campaigns: group customers by behavior, then speak to each segment differently instead of blasting one message at everyone.

ELI10: sort LEGO bricks into 3 piles when nobody names the piles for you. You drop each brick beside the pile it most resembles, then re-center each pile and go again. That is the whole algorithm.

The 5 steps
  1. Choose K — the number of centroids (cluster centers).
  2. Initialize the K centroids. k-means++ initialization places them far apart from each other — better than plain random placement, which can cram two centroids into one region and split a real cluster in half.
  3. Assign every point to its nearest centroid using Euclidean distance.
  4. Update — recompute each centroid as the mean of its assigned points.
  5. Repeat steps 3-4 until assignments stop changing.
Picking K: WCSS and the Elbow Method

WCSS = Within-Cluster Sum of Squares: add up the squared distance from every point to its own centroid. Lower means tighter clusters — but WCSS always falls as K grows (it reaches 0 when K equals the number of points), so the bare minimum is meaningless. The fix: compute WCSS for K = 1 to 10, plot it, and apply the Elbow Method — pick the K at the abrupt change (bend) of the curve, where extra clusters stop paying for themselves.

WCSS = Σ ( squared distance of each point to its own centroid ) → plot for K = 1..10 → pick K at the bend (the elbow)
K-Means vs Hierarchical Clustering

K-means is faster than hierarchical clustering on large datasets; the agglomerative merging gets expensive as data grows. Practical rule: big data → K-means; smaller data where you want a dendrogram and no pre-chosen K → hierarchical (next topic).

💡 Interview angle: Why k-means++ over random init? — it spreads the starting centroids far apart, avoiding bad starts where two centroids land in the same dense region. K-means or hierarchical for millions of rows? — K-means, purely on speed.
