📋 Coach's Review

Common learner gaps in this topic — check yourself against each before the quiz:

① Confusing dendrogram HEIGHT with a data value.
The height of a join is the merge DISTANCE between the two clusters — it is not a spend value, not a coordinate, not a count.
② Comparing points when you should compare clusters.
After the first merge, the algorithm compares CLUSTERS. With single linkage that means the MINIMUM distance between any member of each — skip the matrix update and every later merge is wrong.
③ Assuming K must be chosen in advance.
That is k-means' requirement. Hierarchical clustering's headline advantage is reading K off the dendrogram — no pre-chosen K.
④ Miscounting clusters after the cut.
The number of clusters = the number of vertical lines the horizontal cut CROSSES — not the leaves, not the merges.
⑤ Running it on raw, unscaled features.
One wide-range feature dominates every distance in the matrix and the whole tree is garbage. Standardize first.
⑥ Treating merges as reversible.
Agglomerative merging is greedy: an early bad merge is locked in forever — one reason large, noisy datasets prefer k-means (topic 18).

d({P1,P2},P3) = min(3.1623, 2.0616) = 2.0616  ·  d({P1,P2},{P4,P5}) = min(7.2111, 6.1033) = 6.1033  ·  d(P3,{P4,P5}) = 4.2426 (unchanged)

Step 4 — merge 3: closest is {P1,P2}+P3 at 2.0616 → {P1,P2,P3}. One pair remains:

d({P1,P2,P3},{P4,P5}) = min(6.1033, 4.2426) = 4.2426 ← the final merge height

Step 5 — merge 4 (final): everything joins at 4.2426. The full merge history — the dendrogram — has heights 1.0000 → 1.1180 → 2.0616 → 4.2426.

Step 6 — read the dendrogram: the longest vertical stretch no horizontal line crosses is between 2.0616 and 4.2426 (a jump of 2.18, the biggest in the tree). Cut through it → the cut crosses 2 vertical lines → 2 clusters: {P1,P2,P3} and {P4,P5}.

Business reading: {P4,P5}, centroid (7.5, 5.0) = premium loyalists → VIP retention campaign. {P1,P2,P3}, centroid (2.33, 1.5) = budget browsers → win-back / discount campaign. Want 3 tiers instead? Cut a little lower: {P1,P2}, {P3}, {P4,P5} — P3 emerges as the transitional mid-tier. One tree, several cuts, and the data — not a guess — picked the Ks.

💡 Interview angle: '500 rows, unknown K — what do you run?' Agglomerative, then cut at the longest un-crossed vertical stretch. '1M rows?' K-means — hierarchical merging is too slow at scale.

📝 Notes

The big idea: agglomerative = bottom-up

This section covers agglomerative hierarchical clustering, which builds clusters bottom-up: every point starts as its own cluster (n points → n clusters), and the algorithm repeatedly merges the two closest clusters, one merge per round, until a single cluster remains. Each merge reduces the cluster count by exactly one — n becomes n-1, then n-2, and so on down to 1 — so the whole run is one long merge sequence.

ELI10: nearby villages merge into towns, towns into cities, cities into one country — and every merger gets written down in the family tree.

The dendrogram

That family tree is the dendrogram: it records the full merge history. Each leaf is a single point; every horizontal join is one merge event, and its height shows how far apart the two merged clusters were. Short joins = obvious merges; tall joins = reluctant ones. Cut the same tree at different heights and you get different cluster counts from one run — one cut, one clustering. The dendrogram is the artifact hierarchical clustering gives you and K-means does not.

Choosing the number of clusters (no pre-chosen K!)

The headline advantage: you do not need to pre-choose K. Instead, scan the dendrogram for the longest vertical line that no horizontal line crosses, and pass a horizontal cut through it. The number of vertical lines the cut crosses = the number of clusters. Intuition: that long un-crossed stretch is the biggest jump in merge distance — everything merged below the cut is genuinely similar, while the branches joined above it are truly different groups.

The cost: time

Hierarchical clustering is more time-consuming than K-means on large datasets — the merging keeps comparing cluster pairs as data grows — so it is typically used on smaller datasets. On big data, K-means is the speed pick (topic 18).

💡 Interview angle: Why ever pick agglomerative over K-means? Two reasons from this section: no need to pre-choose K, and the dendrogram hands you a whole family of clusterings you can cut at different levels. The counterpoint? Time — on large datasets K-means wins, which is exactly why big segmentation jobs use K-means.
